# MQSF 2026 presentation

Status: in progress. The first static testbed is implemented; keynote polish,
algorithm updates, and final benchmark results remain.

## Goal and scope

Title: **System Software for Quantum Computing: From the Metal to the User**.
The keynote starts from “Hardware Scales, Software Breaks” and follows real
programs through MQT Core compilation, QDMI, and DDSIM execution. MQSC is the
primary affiliation and TUM the secondary affiliation.

The presentation is static HTML/CSS/JavaScript, with all assets and captured
data available offline from a directly opened HTML file. No runtime backend,
Tailscale, or network dependency. Native computation generates versioned
demonstration fixtures before packaging. Browser animations replay those real
fixtures and explicitly distinguish playback time from execution time.

## Decisions

- Use Shor (15, base 2) as the main example and iterative QPE as a compact
  fallback. Preserve supported control flow and contrast bounded-loop unrolling;
  measurement feedback remains where required.
- Use the bundled Emerald topology and native R/CZ operations, with an explicit
  presentation-only reset/control-flow capability override. Submit compiled
  payloads unchanged to DDSIM. Never claim these capabilities were verified on
  physical Emerald hardware.
- Capture source, compiler stages, exports, mapping, QDMI calls, ordered shots,
  and counts from actual runs. Use Pygments for generated syntax highlighting.
- Adapt the public AFQMC shadow-collection example for a small demonstrable
  workload. Preserve scientific provenance and distinguish recorded longer work.
- Benchpress data is imported when final measurements are available. No invented
  performance numbers or unverified coverage claims.
- Keep native builds and capture generation outside Read the Docs. Hosting uses
  lightweight packaging of committed, curated demonstration fixtures.

## Shared presentation data

Work lives under `presentations/mqsf2026/`. The compiler capture script produces
`captures/programs.json`; execution capture produces `captures/demo.json`. Both
use a JSON object with `schema_version: 1`, `title`, `speaker`, `provenance`,
`device`, and `scenarios`.

`device` has `name`, `label`, `native_gates`, `sites` (objects with integer `id`
and string `name`), and `edges` (integer index pairs). `provenance` records
`core_revision`, `generated_at`, and presentation `patches`.

Each scenario has `id`, `label`, `summary`, `parameters`, and `variants`. Each
variant has `id`, `label`, `stages`, `exports`, and `layout`. Stages/exports
have `id`, `label`, `language`, and exact `code`; packaging adds `html` for
highlighting. `layout` has `initial`, `final`, and `swaps` arrays; only actually
extracted mapping information is included.

Execution adds `execution` to each successful variant: `format`,
`payload_sha256`, ordered bitstring `shots`, `counts`, `duration_ms`, and
`events`. Events carry `time_ms`, `actor`, `target`, `operation`, `status`, and
optional `detail`. Distinguish Python-observed API calls from native traces in
metadata. No synthetic event or shot ordering is accepted as an execution trace.
Unsupported exports or scenarios use an explicit `unavailable_reason` and are
not selectable as successful runs.

The browser consumes one embedded `MQSF_DATA` object. It supports scenario,
variant, compiler stage, and export selection; architecture visualization; QDMI
sequence replay; histogram accumulation; keyboard navigation and print. Only
generated highlighting is inserted as HTML; raw source is otherwise text.

## Validation

Capture checks verify target legality, unchanged submitted payloads, terminal
job success, and equality of shot-derived counts and returned histograms.
Presentation checks verify bundle integrity, no network requirements, and
selection/replay behaviour. Native changes receive focused owning-subsystem
tests and repository C++ lint. The final branch receives an independent review.
Hosted CI status is reported separately from local validation.

The first iteration passes 19 presentation tests with 5 subtests, 70 existing
Shor/QPE/QDMI compilation tests, repository lint, and the offline Chromium
check. An independent review verified fixes for export-specific replay and
validation of every packaged execution. Re-run the commands in the presentation
README after changing captures or presentation behaviour.

## Current limits and next iterations

Shor's native output is large and simulation is slow, so its execution captures
use a small shot budget. QPE provides the compact 64-shot demonstration. Large
artifacts display focused, highlighted excerpts and retain exact full-source
downloads. The Qiskit exporter cannot represent every structured case; missing
exports show their actual diagnostics.

The AFQMC adaptation captures matchgate shadows with a checked angle-sign
convention. Its current Core/PennyLane integration submits separate jobs;
multi-program QDMI jobs, Slurm execution, and classical walker propagation
remain future demonstrations. The application example uses ideal DDSIM directly
and does not claim Emerald mapping.

Future iterations should update the algorithm examples as Core changes, replace
the benchmark placeholder with final full-suite measurements, and polish the
keynote narrative. Rebase this presentation branch on current main before each
native capture refresh. Preserve the committed evidence and validate the new
bundle before replacing a known working offline copy.
