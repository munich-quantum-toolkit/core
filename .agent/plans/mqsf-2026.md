# MQSF 2026 presentation

Status: rebuilt and validated locally. The 28-slide keynote and refreshed native
captures are implemented. Full Benchpress figures and physical rehearsal remain.

## Goal and scope

Deliver **System Software for Quantum Computing: From the Metal to the User** as
a 35-minute keynote for a 1920 × 1080 projector and an audience of about
400. MQSC is the primary affiliation, with TUM and the open-source ecosystem
credited explicitly. Every slide and reveal must work through ordinary clicker
forward/back keys.

The product is a self-contained HTML presentation and ZIP. Native tools generate
evidence before packaging; the browser renders that evidence and replays its
measured timeline without a backend or network connection.

## Current narrative and ownership

The source lives in `presentations/mqsf2026/`. `presentation.js` defines 28
slides and their builds, `presentation.css` owns the fixed 16:9 layout, and
`visuals.js` supplies original SVG illustrations. The sequence opens with the
integration problem, teaches compilation through a three-qubit parity-feedback
program, explains execution with iterative QPE, completes a small H₂ AFQMC
workflow, and returns to HPC integration and the shared ecosystem.

`presenter-notes.md` holds the rehearsal narrative and timing. `README.md` owns
controls, build/capture commands, evidence boundaries, and validation entry
points. Avoid duplicating implementation instructions here.

`capture_programs.py` records exact compiler stages, circuit metadata, mapping,
and exports into `captures/programs.json`. `capture_execution.py` submits the
payloads through the DDSIM device C interface, verifies results, merges the
application, and writes `captures/demo.json.gz`. `capture_afqmc.py` records the
separate application workflow into `captures/afqmc.json`. Intermediate JSON is
untracked; the compressed curated fixture is packaged by `build.py`.

## Durable decisions

Use a small parity-feedback program for compiler explanation. It is readable on
a projector and exposes loops, reset, and measurement control. Use four-qubit
iterative QPE with eight output bits and phase 1/3 for the execution
distribution. Make this change of example explicit in the narrative. Both
structured and bounded-unrolled compiler paths retain the required measurement
feedback.

Use the bundled Emerald coupling graph and native R/CZ operations with explicit
reset/control-flow demonstration assumptions. Execute on local ideal DDSIM.
Captured operand highlighting is not a visualization of the routing search, and
schematic site positions are not chip geometry.

The QIR replay records native API calls and actual shot completions on an
aligned Linux monotonic clock. `MQT_MQSF_SHOT_TRACE` is opt-in demonstration
instrumentation for an isolated single-program worker. It executes each shot
separately, preserves RNG continuity and terminal-state availability, and
disables terminal batch sampling. Its timings include instrumentation and are
not ordinary batch-throughput results. Forward can finish a running replay; back
restores a deterministic previous build.

The application capture performs the full small H₂/STO-3G workflow: one native
512-program QDMI job with 512 shots per program, six reconstructed determinant
overlaps, and 160 classical propagation steps with 64 walkers. Imported helpers
are hash-pinned. The matchgate sign convention, local-energy contract, and
native batch shape are checked. Exact-state and FCI references validate the
result; the shadow-driven trajectory uses measured coefficients. Pointwise bands
describe walker-only uncertainty, conditional on the shadow data.

Retain clear limits: ideal simulation, a tiny active space, finite shadows,
finite projection/step/population effects, and the phaseless approximation.
Slurm and cloud integration are deployment context for this local capture. Do
not claim quantum advantage or extrapolate the small overlap shortcut.

The white/blue deck uses original figurative SVG, canonical project assets, and
embedded fonts. Asset provenance is retained. The QDMI logo is the original
vector wordmark from the supplied AWS/QDMI tutorial, recolored from white to
navy without changing its paths.

Read the Docs and presentation CI only package and inspect recorded evidence;
they do not build LLVM or rerun native computation. The presentation-specific
Read the Docs override must stay isolated from ordinary Core documentation.
